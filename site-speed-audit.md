# Site speed audit

First run July 28, 2026, fixes applied the same day. Re-run any time with
`Rscript scripts/audit-media.R`. Page weight means the HTML plus the local
images the page references. Quarto's listings already lazy-load their
thumbnails, so listing pages fetch images as the visitor scrolls rather
than all at once; the totals below are the full-scroll weight.

## Results

| Group | Before | After |
| ----- | ------ | ----- |
| Everything in `docs/` | 258 MB | 162 MB |
| Images | 43.8 MB | 20.0 MB |
| HTML | 31.6 MB | 17.6 MB |
| PDFs | 84.9 MB | 82.7 MB |
| `site_libs/` (Quarto machinery) | ~90 MB | 35 MB, zero source maps |

| Page | Before | After |
| ---- | ------ | ----- |
| Newsletter archive | 18.6 MB | 7.5 MB |
| 2023 schedule | 8.3 MB | 0.4 MB |
| Telepsychology (both pages) | 3.2 MB each | 0.2 MB each |
| Home page | 1.8 MB | 1.1 MB |
| Awards banner file | 7.1 MB | 0.1 MB |

## What was fixed

**Awards banner.** The 7.1 MB SVG was a 3008x2000 photo and a clipping
mask stored as base64 inside the file. No image tool could parse it, so
the SVG was rendered in a browser, captured at 1600 px, and saved as a
103 KB JPG. `awards/index.qmd` now points at the JPG and the page looks
the same.

**Newsletter images.** All 154 cover and featured images under
`resources/newsletter/` were resized to 800 px maximum and compressed in
place (pngquant for PNG, quality 82 for JPEG), keeping the same
filenames, so no page edits were needed.

**Conference images.** 114 files under `conferences/` got the same
treatment (17 MB to 10 MB). The 2023 sponsor montage is generated by an
R chunk, so the compressed copy was written into the `_freeze` store
instead; that way future re-renders keep the 251 KB version rather than
regenerating the original 2.8 MB one.

**site_libs cleanup.** The pages only use reactable 0.4.5, but the build
folder carried unreferenced 0.4.3 and 0.4.4 copies. The 0.4.3 folder
alone held 410 Finder-duplicate files (`reactable 10.js`, and so on).
All four stale folders were deleted along with every `.map` source map,
which browsers never fetch outside of devtools. To keep this from
growing back, `scripts/clean-site-libs.R` now runs after every render
through the `post-render` hook in `_quarto.yml`, because the reactable
package ships fresh source maps each time.

**Telepsychology pages.** The 3.2 MB per page came from the table code
embedding the same 980x980 link icon as base64 in all 80 rows, even
though it displays at 30x30. The icon was resized to 64 px (1 KB, same
filename) and the pages re-rendered. No text changed.

**2023 schedule page.** The `downloadthis` shortcode was embedding the
5.8 MB program grid PDF as base64 in the HTML. It was replaced with a
direct download link that keeps the same "Program Grid" label, icon,
and button style. No text changed.

**PDFs.** Nine oversized PDFs were recompressed with ghostscript at
/ebook settings, with page counts verified by pdfinfo before keeping
each one. That saved about 1.4 MB. The two 5.8 MB 2023 program files
came back larger from every attempt, so they were left alone; they are
already as small as they get without visible quality loss.

## What remains, and why it is fine

- The newsletter archive is still the heaviest page at 7.5 MB, but that
  is 112 thumbnails that lazy-load as the visitor scrolls. Nothing to
  fix.
- `telepsychology.qmd` and `index.qmd` in `resources/telepsychology/`
  are near-duplicates and both still build. Worth deciding someday
  whether both are needed, but neither is heavy anymore.
- One empty file (`conferences/archive/2023/images/guidebook.png`,
  zero bytes, referenced nowhere) was deleted during the cleanup.

## Fix playbook

1. Compress the **source** files, never the copies in `docs/`. `docs/`
   is build output; re-render to refresh it. Source images sit next to
   their pages at the same relative paths this report shows for `docs/`.
2. One-off images: squoosh.app. Bulk work:
   `scripts/optimize-media.sh <dir>` (needs `gs`, `magick`, `pngquant`).
3. After compressing, render the affected pages (or the whole site) and
   spot-check that listings still show their thumbnails.
4. Re-run `Rscript scripts/audit-media.R` to confirm the savings.
5. You do not need to delete `.map` files by hand. The post-render hook
   in `_quarto.yml` handles them on every build.
